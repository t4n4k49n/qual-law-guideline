## 背景
- PR本文の文字化け/崩れ対策をローカルとCIの両方で一貫して強制し、PR作成後にCIで気付く運用をなくす。
- 既存の保護を維持したまま、hook配線差異やPR本文入力経路の差による抜けを塞ぐ。

## 変更内容
- `.githooks/` を追加し、`pre-commit` / `pre-push` をリポジトリ管理下で固定。
- `scripts/install_git_hooks.py` を追加し、`core.hooksPath=.githooks` を設定可能にした。
- `scripts/run_guard_stage.py` を追加し、既存ガードを stage ごとに統合実行。
- `scripts/check_user_dir_leak.py` を `.git/hooks` 依存から `scripts/` 配下へ移設。
- `scripts/check_pr_body_content.py` を調整し、引数指定時は対象ファイルのみ検査して全体走査へフォールバックしないようにした。
- `scripts/check_pr_body_live_local.py` を追加し、pre-push時に `gh pr view` で現在PR本文を取得して marker/content 一致を検証。
- `scripts/gh_pr_guard.py` を追加し、`gh pr create/edit` 実行時に `--body-file` 必須、repo相対path必須、marker整合必須を強制。
- `README.md` と `docs/NORMALIZED_RUN_PLAYBOOK.md` に、ローカルhook有効化の最小手順のみ追記。

## テスト

  - `tests/test_check_pr_body_live_local.py`

## まとめ
PR本文ポリシーを、ローカル（commit/push前）とCI（pull_request_target）の両方で強制する構成に統一した。これにより、本文崩れ・marker欠落・本文ファイル不整合をPR作成前に検知し、レビュー開始前に修正できる状態にした。
