## 背景
- PR #125 で「PR本文の文字化け対策」を導入したが、ローカル環境では git hook 配線の差異により、commit/push 前に同等ガードが必ず実行される状態になっていなかった。
- その結果、PR作成自体は通ってしまい、CI側で初めて検知される運用上の穴が残っていた。

## 変更内容
- `.githooks/` を新設し、`pre-commit` / `pre-push` をリポジトリ管理下で明示化。
- `scripts/install_git_hooks.py` を追加し、`core.hooksPath=.githooks` を標準化。
- `scripts/run_guard_stage.py` を追加し、既存ガードを stage 別に統合実行。
- 既存の `check_user_dir_leak.py` を `.git/hooks` 依存から `scripts/` に移設。
- README と 正規化RUN Playbook に hook 初期化手順を追記。

## テスト
- 既存ガード + 新規ガードの回帰テストを実行。
- 結果: 26 passed
  - `tests/test_check_pr_body_content.py`
  - `tests/test_pr_body_guard_lib.py`
  - `tests/test_check_pr_body_escape_policy.py`
  - `tests/test_check_bidi_controls.py`
  - `tests/test_check_parent_root_notes_absent.py`
  - `tests/test_check_parent_local_notes_boundary.py`
  - `tests/test_check_venv_runtime.py`
  - `tests/test_check_venv_command_policy.py`
  - `tests/test_run_guard_stage.py`
  - `tests/test_install_git_hooks.py`

## まとめ
PR #125 で導入した本文保護を補完し、ローカルでも commit/push 前にガードが確実に走るようにした。これにより、文字化けや本文崩れの検知タイミングをPR作成後のCIから、作成前のローカルへ前倒しできる。
