# 個別アダプタ検討メモ

## 背景

原薬GMPガイドラインの表1は、PDF由来TXT上で固定幅表として崩れている。

共通 `text2ir` parser に「崩れた固定幅表を緩くtable化する」挙動を入れる案を一度検討したが、この挙動はAPI GMPの表1に強く依存するため採用しなかった。

## 試した案

- `detect_plaintext_tables.allow_ragged` のような設定で、列数が一致しない固定幅行もtable rowとして受ける。
- キャプション直後の非固定幅説明行を、表のraw rowとして許容する。

## 採用しなかった理由

- 共通parserの表検出が緩くなり、他文書で通常本文をtable扱いするリスクがある。
- 表1は列構造を完全復元するより、本文階層を壊さずに保持することが今回の完了条件に合う。
- 6/7/8/9のうち、同じ崩れ方をする表が複数確認されるまでは共通化しない方がよい。

## 今回の採用方針

RUN内の整形済み入力 `input/000156438_table1_markdown.txt` を作成し、表1のみを1列markdown tableへ置換した。

- 原文の行内容は保持する。
- 列復元はしない。
- IRでは `table -> table_header -> table_row` として保持する。
- 正式昇格候補はこの整形済み入力から再生成する。

## 将来の個別部品候補

- `api_gmp_table1_adapter`
  - 入力: PDF抽出TXTの表1ブロック
  - 出力: markdown tableまたは専用table row構造
  - 責務: 表1の行保持、必要なら後段で列推定
- 共通parserへ昇格する条件
  - 複数文書で同じ崩れ方が再発する
  - 誤検出を抑える明確なcaption/row境界条件を定義できる
  - 既存tableテストで通常本文の誤table化が増えない
